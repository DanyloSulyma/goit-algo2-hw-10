Висновки task1 (Аналіз результатів):
- Ефективність на випадкових даних: Обидва алгоритми демонструють практично ідентичний час роботи на випадкових наборах даних (складність O(N \log N)$). Різниця в часі зазвичай знаходиться в межах мілісекунд.
- Накладні витрати: Детермінований алгоритм часто виявляється на крихітну долю секунди швидшим за рахунок відсутності необхідності щоразу викликати функцію random.randint(), яка додає незначні накладні витрати на рівні процесора.
- Захист від найгіршого випадку: Попри те що детермінований алгоритм трішки швидший на випадковому масиві, рандомізований QuickSort є значно надійнішим. У детермінованого підходу (навіть якщо обирається центральний елемент) існують специфічні "найгірші" масиви, які знизять його ефективність до $O(N^2)$. Рандомізований вибір опорного елемента робить імовірність потрапляння в найгірший сценарій математично нескінченно малою незалежно від характеру вхідних даних.
